The `Entity` and `File` models each have a nullable JSON column, `meta`, for your own data. arocapi never puts `meta` in
an API response, so it can hold storage locations and internal flags.

| Column        | Passed to                                                             | Typical use                              |
| ------------- | --------------------------------------------------------------------- | ---------------------------------------- |
| `Entity.meta` | [`roCrateHandler`](/configuration/handlers/#rocratehandler), and your [`entityVisibilityFilter`](/configuration/visibility/#entityvisibilityfilter) can query it | Where the RO-Crate metadata is stored; visibility flags such as drafts. |
| `File.meta`   | [`fileHandler`](/configuration/handlers/#filehandler)                 | Where the file's bytes are stored.       |

The file handler receives the `File` row and its own `meta`, not the file entity's. Put what the file handler needs on
the `File` row. [Storage](/strategies/storage/) shows handlers reading locations from `meta`.

`meta` is typed as Prisma's `JsonValue`, so narrow it before reading fields:

```ts twoslash
import type { FileHandler } from 'arocapi';

const storagePath = (meta: unknown) => {
  if (typeof meta === 'object' && meta !== null && 'storagePath' in meta && typeof meta.storagePath === 'string') {
    return meta.storagePath;
  }

  throw new Error('File has no storagePath');
};

const fileHandler: FileHandler = {
  get: (file) => ({ type: 'redirect', url: `https://storage.example.com/${storagePath(file.meta)}` }),
  head: (file) => ({ contentType: file.mediaType, contentLength: Number(file.size) }),
};
```

## Visibility flags

A flag in `Entity.meta` can drive the [visibility filters](/configuration/visibility/). Mirror it into your search
index, for example as `meta.draft`, so the search filter can match the same entities. In Prisma, a plain `not` on a
JSON path also excludes rows where `meta` or the path is null, so match those explicitly:

```ts twoslash
type EntityWhere = Awaited<ReturnType<import('arocapi').EntityVisibilityFilter>>;
type JsonFilter = Extract<NonNullable<EntityWhere['meta']>, { equals?: unknown }>;
declare const Prisma: { AnyNull: NonNullable<JsonFilter['equals']> };
// ---cut---
import type { EntityVisibilityFilter, SearchVisibilityFilter } from 'arocapi';

const entityVisibilityFilter: EntityVisibilityFilter = () => ({
  OR: [{ meta: { path: '$.draft', equals: Prisma.AnyNull } }, { meta: { path: '$.draft', not: true } }],
});

const searchVisibilityFilter: SearchVisibilityFilter = () => ({
  bool: { must_not: { term: { 'meta.draft': true } } },
});
```

`Prisma` here is the namespace from your generated Prisma client. JSON path filters can't use an index on MySQL; for
large repositories, store visibility flags in your own indexed columns.
