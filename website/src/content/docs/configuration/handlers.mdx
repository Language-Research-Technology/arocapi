Handlers fetch bytes from your storage. arocapi calls them only after the entity is Visible and the request has access,
so they don't need their own checks (see the [request
lifecycle](/concepts/request-lifecycle/#metadata-and-content-routes)). [Storage](/strategies/storage/) compares ways to
serve bytes from local disk, object storage and OCFL.

| Option           | Required | Type             | Default | Purpose                                                  |
| ---------------- | -------- | ---------------- | ------- | -------------------------------------------------------- |
| `fileHandler`    | yes      | `FileHandler`    | none    | Serve a file's Content for `GET` and `HEAD /file/:id`.   |
| `roCrateHandler` | yes      | `RoCrateHandler` | none    | Serve an entity's RO-Crate metadata for `/entity/:id/metadata`. |

Both are objects with a `get` and a `head` function. Each receives a database row and the
[request context](/configuration/transformers/#request-context), and may be async.

| Function              | Receives                            | Returns                     |
| --------------------- | ----------------------------------- | --------------------------- |
| `fileHandler.get`     | `File` row, including `file.meta`   | `FileResult \| false`       |
| `fileHandler.head`    | `File` row, including `file.meta`   | `FileMetadata \| false`     |
| `roCrateHandler.get`  | `Entity` row, including `entity.meta` | `FileResult \| false`     |
| `roCrateHandler.head` | `Entity` row, including `entity.meta` | `FileMetadata \| false`   |

Returning `false` answers 404 `NOT_FOUND`. The `meta` columns hold whatever your handlers need to find the bytes; see
[Entity meta](/reference/entity-meta/).

`/entity/:id/metadata` always answers `GET` with `Content-Type: application/ld+json`, whatever `contentType` the
handler returns.

## Results

`get` returns one of three `FileResult` types:

| `type`     | Fields                                  | Response                                                               |
| ---------- | --------------------------------------- | ---------------------------------------------------------------------- |
| `redirect` | `url`                                   | 302 to `url`. `/file/:id?noRedirect=true` answers 200 `{ "location": url }` instead. |
| `stream`   | `stream`, `metadata`                    | 200 with the stream as the body. `stream` is a Node `Readable` or a web `ReadableStream`. |
| `file`     | `path`, `metadata`, `accelPath?`        | 200 with the file at `path` (absolute). With `accelPath`, an empty body and `X-Accel-Redirect: <accelPath>` for nginx to serve. |

`head` and the `metadata` field return a `FileMetadata`, which becomes the response headers:

| Field           | Type      | Header           |
| --------------- | --------- | ---------------- |
| `contentType`   | `string`  | `Content-Type`   |
| `contentLength` | `number`  | `Content-Length` |
| `etag`          | `string?` | `ETag`           |
| `lastModified`  | `Date?`   | `Last-Modified`  |

## Range requests

arocapi doesn't handle `Range` headers. A `stream` or `file` result is always sent whole, with the full
`Content-Length`. For seeking in audio and video, return a `redirect` to storage that supports ranges, such as a
presigned object storage URL, or a `file` result with `accelPath` so nginx serves the range. See
[Range requests](/strategies/storage/#range-requests) in the storage strategies.

## Query parameters

`GET /file/:id` accepts:

| Parameter     | Values                   | Default         | Effect                                                      |
| ------------- | ------------------------ | --------------- | ----------------------------------------------------------- |
| `disposition` | `inline` or `attachment` | `inline`        | `Content-Disposition` type for `stream` and `file` results. |
| `filename`    | string                   | `file.filename` | Filename in `Content-Disposition`.                          |
| `noRedirect`  | `true` or `false`        | `false`         | Answer a `redirect` result with 200 `{ "location": url }`.  |

Any other `disposition` or `noRedirect` value is a 400. `/entity/:id/metadata` takes no query parameters.
