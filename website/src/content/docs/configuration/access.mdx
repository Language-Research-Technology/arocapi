Access decides whether a request may read a Visible entity's Metadata (its RO-Crate metadata document) and Content (a
file's bytes). arocapi attaches the result to every entity and file it returns, and enforces it on
`/entity/:id/metadata` and `/file/:id` before calling your handlers. See
[Record, Metadata, Content](/concepts/record-metadata-content/) for the levels and
[Visibility vs Access](/concepts/visibility-vs-access/) for how a request is decided.
[Access strategies](/strategies/access/) compares common ways to decide access.

| Option            | Required | Type              | Default     | Purpose                                                  |
| ----------------- | -------- | ----------------- | ----------- | -------------------------------------------------------- |
| `access`          | yes      | `AccessFunction`  | none        | Decide Metadata and Content access for an entity.        |
| `isAuthenticated` | no       | `IsAuthenticated` | none        | Tell anonymous requests (401) from authenticated (403). |

## `access`

Called with the entity as a `BaseEntity` and the [request context](/configuration/transformers/#request-context). It
returns an `AccessInfo`:

| Field                      | Type      | Purpose                                                  |
| -------------------------- | --------- | -------------------------------------------------------- |
| `metadata`                 | `boolean` | Whether the request may read the entity's Metadata.      |
| `content`                  | `boolean` | Whether the request may read the file's Content.         |
| `metadataAuthorizationUrl` | `string?` | Where to request Metadata access. Kept only when truthy. |
| `contentAuthorizationUrl`  | `string?` | Where to request Content access. Kept only when truthy.  |

Anything else it returns is dropped.

- `BaseEntity` has the Record fields, with `memberOf` and `rootCollection` as ids. arocapi doesn't look up parents.
- It runs once per entity in a listing and once per Metadata or Content request. Cache remote lookups per request.
- A file's access is its file entity's access. On collections and objects, `content` is only a signal to clients.
- When access is false, `/entity/:id/metadata` and `/file/:id` refuse the request and never call your handler.

For a public repository, use `AllPublicAccess`, which grants everything:

```ts twoslash
import { AllPublicAccess, type Options } from 'arocapi';

const access: Options['access'] = AllPublicAccess;
```

When access follows licences, use `LicenceAccess`. Metadata needs the entity's `metadataLicenseId` and Content its
`contentLicenseId`. Each licence is checked at most once per request. See
[licence checks against an external authority](/strategies/access/#licence-checks-against-an-external-authority)
for caching a user's entitlements across licences.

```ts twoslash
declare function licencesHeldBy(request: import('arocapi').RequestContext['request']): Promise<string[]>;
// ---cut---
import { LicenceAccess } from 'arocapi';

const access = LicenceAccess({
  hasLicence: async (licenceId, { request }) => (await licencesHeldBy(request)).includes(licenceId),
  authorisationUrl: (licenceId) => `https://rems.example.com/apply?resource=${encodeURIComponent(licenceId)}`,
});
```

| `LicenceAccess` option | Required | Type                                                     | Purpose                                                  |
| ---------------------- | -------- | -------------------------------------------------------- | -------------------------------------------------------- |
| `hasLicence`           | yes      | `(licenceId, context) => boolean \| Promise<boolean>`    | Whether the request holds a licence.                     |
| `authorisationUrl`     | no       | `(licenceId) => string`                                  | Authorisation URL to attach when a licence isn't held.   |

For any other rule, write your own function:

```ts twoslash
declare function currentUser(request: import('arocapi').RequestContext['request']): { isStaff: boolean } | undefined;
// ---cut---
import type { AccessFunction } from 'arocapi';

const access: AccessFunction = (entity, { request }) => {
  const user = currentUser(request);

  return {
    metadata: true,
    content: Boolean(user?.isStaff),
    contentAuthorizationUrl: user ? undefined : 'https://auth.example.com/login',
  };
};
```

## `isAuthenticated`

Returns whether the request carries valid credentials. arocapi uses it to pick the status of a refusal: 401 for an
anonymous request, so the client can prompt a login, and 403 when logging in won't help; see
[Denied is 401 or 403, never 404](/concepts/visibility-vs-access/#denied-is-401-or-403-never-404).

```ts twoslash
declare function currentUser(request: import('arocapi').RequestContext['request']): object | undefined;
// ---cut---
import type { IsAuthenticated } from 'arocapi';

const isAuthenticated: IsAuthenticated = ({ request }) => currentUser(request) !== undefined;
```

Without it, the repository has no logins: no request is anonymous, so a Denied request always gets 403. It is required
by [`promptLoginForHidden`](/configuration/visibility/#promptloginforhidden). See
[Error responses](/reference/errors/#refusals) for every outcome.
